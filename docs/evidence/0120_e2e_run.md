- Project artifacts included uploaded table artifacts, relational catalog artifacts, chat/report artifacts, and session artifacts.
- No `task_spec` or primary DatasetSnapshot was registered during the observation window.

Root cause found from code inspection:

- H1 says Codex can later call `set_primary_table` with either `dataset_snapshot_id` or `artifact_id`.
- Primary-free upload can leave uploaded tables as table artifacts before any DatasetSnapshot exists.

Fix applied:

- `set_primary_table` with an uploaded table `artifact_id` now profiles that artifact into a DatasetSnapshot when needed, then selects it as primary.
- This keeps the harness out of target/task inference while allowing Codex's fixed-format primary-table declaration to pass.
