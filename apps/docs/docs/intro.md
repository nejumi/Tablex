# Tablex documentation

Tablex is an agentic workbench for tabular prediction projects. It helps a data science agent work with your data while the product keeps the project state understandable: data, objectives, evaluation contracts, notebooks, model results, prediction pipelines, assets, and operational feedback all stay linked.

![Tablex Home workspace](/img/screenshots/home-workspace-placeholder.svg)

## What Tablex is for

Tablex is useful when a tabular project is not just "upload a CSV and train a model." A project may have multiple tables, uncertain row grain, delayed outcomes, derived targets, leakage risks, external research, and human decisions about evaluation. Tablex keeps those moving parts visible while Codex or another agent reasons over them.

## The main loop

1. Upload one or more data files.
2. Decide or defer the objective.
3. Let Full Auto inspect the data, create notebooks, propose evaluation, train baselines, and register model results.
4. Review notebooks, reports, the leaderboard, and assets from the product UI.
5. Run prediction batches or pilot validation when you have target-free input or later outcomes.
6. Feed new evidence back into the same project so the agent can audit, repair, or improve the work.

## How to read the UI

Tablex has a few primary surfaces:

- Home: the current project story, agent chat, research plan, and recommended next action.
- Data: uploaded datasets, primary table selection, objective setup, and profiles.
- Insight: readable reports, research findings, and human-facing outputs.
- Evaluation: candidate metrics and split designs.
- Leaderboard: model runs, evidence, diagnostics, prediction, and pilot actions.
- Assets: the canonical inventory of files, notebooks, reports, pipelines, and evidence.

## English is the canonical documentation

The English documentation is the source of truth. Japanese, Simplified Chinese, and Korean pages are translated from the same page paths and should be updated after English changes.
