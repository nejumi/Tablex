# 评估

评估是 Tablex 项目的脊梁。只有当你知道比较了哪些行、如何切分、使用什么指标，以及控制了哪些泄漏风险时，模型分数才有意义。

## 临时结果与正式结果

临时结果适合探索。它们可能来自智能体创建的内部交叉验证。除非评估契约已被批准，否则应把它们视为方向性结果。

正式结果会注册到已批准的评估设计上。它们是应该用于持久比较的数字。

## EvaluationSpec

EvaluationSpec 定义指标和评分策略。例如二分类的 ROC-AUC、回归的 MAE、概率质量的 log loss，或领域特定指标。

## SplitManifest

SplitManifest 定义哪些行属于训练、验证、测试或 fold。它对泄漏控制、分组实体、时间感知验证和可重复比较很重要。

## 信任分数前要检查什么

- 目标定义清楚。
- 切分方式匹配预测场景。
- 不应跨 fold 的实体确实没有跨 fold。
- 未来信息没有进入训练特征。
- 指标匹配你关心的决策。
- Leaderboard 行链接到 Notebook、诊断或报告。

## 修改评估

不要原地重写已批准的评估。创建新的候选或版本，进行比较，并让变更理由可见。
